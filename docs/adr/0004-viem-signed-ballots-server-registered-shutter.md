# Ballots are signed with viem, not the EAS SDK; the server triggers Shutter registration

The EAS SDK depends on ethers, which would duplicate viem and add weight for one signing call, so ballots are EIP-712-signed with viem using the SDK's own domain and types, and the SDK is a dev-only dependency whose cross-check test must agree on UIDs and signature verification. The creator's "Open the feast" makes the server call the Shutter API, which registers the feast's identity on-chain and can cover the gas, so scatterers never transact and the creator signs no transaction. Rejected: client-side registration (a Gnosis transaction per creator) and a funded server wallet (kept only as the fallback design if the API's gas coverage requires a plan we do not take). See `docs/04-technical-spec.md` §6–§7, T3, T14.
