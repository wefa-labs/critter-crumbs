# Foundry named-keystore sender

Verified 2026-09-06 from installed `cast 1.7.1`, commit `4072e48705af9d93e3c0f6e29e93b5e9a40caed8`, its `send --help`, and pinned primary source. A named keystore can supply the existing `Account.sendTransaction` seam without a private-key or password argument. No keystore was opened by the researcher, no password was requested, and no signer or chain call was exercised; prompt and submission findings below are source-derived.

## Invocation and prompt

The supported invocation shape is:

```text
cast send <destination> --account <name> --chain 84532 --data <calldata> --async
```

Supply the selected endpoint through child `ETH_RPC_URL`. The RPC option resolves that variable explicitly, even though the installed help does not list it beside `--rpc-url`; an explicit RPC flag would take precedence. Supply chain, destination and calldata explicitly. `--chain` sets the signing chain; it does not prove the RPC serves that chain, so retain the application's independent chain-ID preflight. [RPC option source](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/cli/src/opts/rpc.rs#L68-L85), [chain selection](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/cli/src/utils/mod.rs#L114-L122)

`--account NAME` resolves `~/.foundry/keystores/NAME`. Without either password source, the wallet helper creates a pending keystore signer and unlocks it through `rpassword::prompt_password("Enter keystore password:")`. Neither `--password-file` nor `--interactive` is needed; the latter prompts for a raw private key. Validate the wrapper's account name as a filename because the underlying helper joins it onto the directory. [Wallet options](https://github.com/foundry-rs/foundry-core/blob/b9ff33dce891b7e7c0f20056b72aea5e3a36314e/crates/wallets/src/opts.rs#L204-L218), [path/password helper](https://github.com/foundry-rs/foundry-core/blob/b9ff33dce891b7e7c0f20056b72aea5e3a36314e/crates/wallets/src/utils.rs#L89-L151), [unlock callsite](https://github.com/foundry-rs/foundry-core/blob/b9ff33dce891b7e7c0f20056b72aea5e3a36314e/crates/wallets/src/signer.rs#L325-L345)

On macOS/Unix, the pinned `rpassword 7.4.0` reads `/dev/tty` with echo disabled; its `rtoolbox 0.0.4` prompt writer separately opens `/dev/tty` for writing. The prompt uses neither stdout nor stderr. A non-detached child can therefore inherit stdin, pipe stdout for the hash, and ignore/capture stderr while the human unlocks through its controlling terminal. Absence of that terminal must fail; do not substitute a password file or have the wrapper read the password. This was not tested against a real keystore. [Password source](https://docs.rs/crate/rpassword/7.4.0/source/src/lib.rs), [TTY output source](https://docs.rs/crate/rtoolbox/0.0.4/source/src/print_tty.rs)

## Environment and output boundary

Use a small child environment: required ordinary process/terminal variables such as `HOME`, `PATH`, `USER`, `LOGNAME`, `TERM`, `COLORTERM`, `TMPDIR`, optionally `XDG_CONFIG_HOME`, and the explicit selected `ETH_RPC_URL`. Do not forward password/signing/transaction overrides such as `ETH_PASSWORD` (a password-file path), `ETH_KEYSTORE`, `ETH_KEYSTORE_ACCOUNT`, `ETH_FROM`, `TEMPO_ACCESS_KEY`, `TEMPO_ROOT_ACCOUNT`, `CHAIN`, gas settings or arbitrary Foundry/log/RPC-header variables. Explicit `--account` conflicts with an inherited `ETH_KEYSTORE`; Tempo access-key selection precedes the keystore path. Avoid raw-key, mnemonic, unlocked-node, browser or hardware flags in this named-keystore sender. [Wallet selection](https://github.com/foundry-rs/foundry-core/blob/b9ff33dce891b7e7c0f20056b72aea5e3a36314e/crates/wallets/src/opts.rs)

**An environment allowlist alone is insufficient:** Cast's startup calls `load_dotenv()`, which loads `.env` from the detected project root and current directory before argument parsing. Run the child in a controlled temporary directory outside project ancestry to prevent those files from reintroducing stripped options. Preserve the real `HOME` so the chosen existing keystore remains discoverable. Cast may still load the user's global `~/.foundry/foundry.toml`; isolated cwd is not a claim that all Foundry configuration is disabled. No local environment-file contents were inspected or printed during this research. [Startup](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/cast/src/args.rs#L36-L50), [dotenv loading](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/cli/src/utils/mod.rs#L169-L198), [global configuration loading](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/config/src/lib.rs#L900-L911)

After successful submission, `--async` prints `0x` plus the 64 hexadecimal hash characters and a newline, without waiting for a receipt. Accept a successful exit and exactly one trimmed transaction hash; reject extra/malformed output. Do not expose raw stderr on failure: provider errors can contain endpoint URLs or response bodies. Return the wrapper's controlled error. The existing viem receipt/confirmation verifier remains responsible for mined success. [Hash output](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/cast/src/tx.rs#L288-L306), [submission flow](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/cast/src/cmd/send.rs)

## Retry limit

The wrapper should launch once and never automatically rerun a failed invocation. **Foundry itself can retransmit RPC requests:** its provider installs Alloy's retry layer with `max_retry = 8` and initial backoff 800 ms. The pinned Alloy transport clones the same request packet when its error policy permits retry, without excluding submission methods; this includes certain rate-limit/unavailable responses and missing responses. `--async` skips receipt waiting, not transport retries. No zero-retry `cast send` flag was established from the installed help or this provider path. [Foundry provider](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/common/src/provider/mod.rs#L200-L204), [retry installation](https://github.com/foundry-rs/foundry/blob/4072e48705af9d93e3c0f6e29e93b5e9a40caed8/crates/common/src/provider/mod.rs#L368-L408), [Alloy 2.0.1 retry implementation](https://docs.rs/crate/alloy-transport/2.0.1/source/src/layers/retry.rs)

A failed process or lost stdout does not prove that no transaction was accepted. Preserve the existing schema-UID/read-before-write and receipt recovery checks; do not blindly relaunch, since rebuilding can choose another nonce. Tests should use a fake external process to pin argv, environment/cwd isolation, accepted hash output and controlled failures. They must not unlock an actual account.
